# KMA 프로젝트

**일은 프로젝트 단위로 돕니다.** 고객사 × 과정 한 건이 프로젝트 하나이고,
그 안에서 **제안서**와 **결과보고서** 두 문서를 만듭니다. 나머지는 그 두 문서를 채우는 재료입니다.

```
프로젝트 (고객사 × 과정)
├─ 제안서       커리큘럼 파일 → 템플릿 → 제안서 .pptx + 예산서(계획)
│                 ├─ 외부용 견적서  원가·이익률을 뺀 고객 제출용 .xlsx
│                 └─ 메일 보내기    아웃룩으로 담당자에게 바로
└─ 결과보고서   만족도 · 정산 · 교육사진 · 영수증 → 결과보고서 .pptx + 정산표
                 ├─ 정산·견적서   제안 예산(계획) ↔ 실제 집행액
                 ├─ 교육사진      방향 보정 · 중복 검토 · 행사위치별 파일명 → zip
                 ├─ 영수증        ERP 업로드용 파일명 + PDF + 계정 분류
                 └─ 메일 보내기    아웃룩으로 담당자에게 바로
```

| 화면 | 하는 일 |
|---|---|
| **프로젝트** (첫 화면) | 수주 한 건의 워크플로우 — 제안서 → 발송 → 수주 → 운영 → 결과보고서 → 전달 |
| **제안서** | 교수님께 받은 커리큘럼 파일 → 내 템플릿에 채우기 → **제안서 .pptx** + PMS 예산서 |
| **결과보고서** | 만족도 조사 분석 + 정산 + 사진 + 영수증 → **결과보고서 .pptx** + 정산표 |

> 견적서·교육사진·영수증은 **결과보고서 안의 탭**으로 들어가 있습니다.
> 따로 도는 도구가 아니라, 열려 있는 프로젝트의 것으로 묶여 정산에 자동으로 잡힙니다.
>
> **만들어진 문서는 아웃룩으로 바로 나갑니다.** 담당자 메일 주소만 넣으면 됩니다.

## 폴더 구조 · 실행 · 배포

```
public/          브라우저에 나가는 정적 파일 (index.html · admin.html · styles.css · js/ · templates/)
api/index.py     Vercel 서버리스 함수 — /api/* 전부 (vercel.json 의 rewrites)
server/          API 로직 (relay.py 와 api/index.py 가 같이 쓴다)
  data/          서버만 읽는 캐시 — teachers.json · notion-proposals.json
relay.py         로컬 서버 (python relay.py — 실행하기.bat 은 이것을 띄우는 바로가기일 뿐)
forms/           견적서 엑셀 양식 (서버 함수만 읽는다 — 공개 파일로 나가지 않음)
server/sql/      Supabase 에 한 번 돌리는 SQL (계정 표)
.env             비밀 값 — 커밋·공유 금지 (.env.example 이 서식)
```

**PPT · 엑셀 · 메일은 오피스를 부르지 않는다.** 예전에는 PowerShell 로 파워포인트·엑셀·아웃룩을
띄워서(COM) 윈도우 + 실행하기.bat 에서만 됐다. 이제는 파일 속 XML 을 직접 고친다
(`server/pptx.py` · `xlsx.py` · `mail.py`). 그래서 **로컬과 배포한 웹이 똑같이 돈다.**
진짜 파워포인트로 연 566개 글상자의 줄 수에 맞춰 글 폭 계산을 맞췄고(97% 일치), 만든 파일은
파워포인트·엑셀로 열어 복구 창 없이 열리는 것을 확인했다.

**로컬** — `python relay.py` (또는 `실행하기.bat`). `.env` 를 읽는다.
AI 커리큘럼은 `py -m pip install -r requirements.txt` 한 번.

**Vercel** — 저장소를 연결하거나 `vercel` 로 올린다. 빌드 설정은 비워 둔다(`vercel.json` 에 있음).
처음 한 번만:
1. Settings → Environment Variables 에 `.env` 내용을 넣는다 (`SUPABASE_URL` · `SUPABASE_SECRET_KEY` 는 꼭).
2. Supabase → SQL Editor 에서 `server/sql/001_accounts.sql` 을 실행한다 (계정 표 · 예전 계정 옮기기).
3. 로컬에서 올려 둔 PPT 양식을 웹 보관소로: `python -m server.storage_sync --go`

배포한 웹은 **로그인해야 쓸 수 있다** — 누구나 부를 수 있는 주소라서, 로그인 없이 열어 두면
노션 교육문의를 아무나 읽고 Claude API 비용이 나간다. 큰 파일(양식·사진·만든 PPT)은
Vercel 의 4.5MB 한도를 피해 Supabase Storage(비공개 통 `kma-files`)를 거친다(`server/files.py`).
배포본은 디스크를 쓸 수 없어서, 강사 색인·지난 제안서를 새로 읽으면 잠깐만 기억하고
(함수가 식으면 사라진다) 평소에는 `server/data/` 에 실려 간 캐시를 쓴다.

## 평가 기준에 대한 답

### 1. 발전 가능성 — 타 부서 적용 · 고도화

**부서에 매인 값은 네 곳에만 있습니다.** 나머지는 전부 화면에서 바꿉니다.

| 무엇 | 어디 | 어떻게 |
|---|---|---|
| 사이트 이름 | [`js/core/shell.js`](js/core/shell.js) 맨 위 두 줄 | 코드 두 줄 |
| 원가 계정 구분표 | [`js/apps/receipt/accounts.js`](js/apps/receipt/accounts.js) | 표가 개정되면 이 파일만 |
| 견적서 공급자 정보 | — | **화면에서** (`공급자 정보`), 이 PC 에 저장 |
| 보내는 사람·서명 | — | **화면에서** (`내 정보`), 이 PC 에 저장 |
| 제안서·결과보고서 양식 | — | **화면에서 PPT 파일을 올림** |

- **양식이 코드에 박혀 있지 않습니다.** 부서마다 쓰는 제안서 양식이 다른데, 그 부서 PPT 를 올리면
  그대로 돌아갑니다. 코드를 고칠 일이 없습니다.
- **도구를 붙이고 떼는 자리가 정해져 있습니다.** 각 화면은 `mount / unmount / stat / metrics /
  exportData / importData` 여섯 개만 지키면 됩니다. 실제로 과정 운영 관리와 고객사 관리를
  **코드를 지우지 않고 목록에서 빼는 것만으로** 떼어 냈고(`_ops-보류/`, `_고객사-보류/`),
  증빙과 교육사진은 상단 탭에서 결과보고서 안 탭으로 **옮겨 붙였습니다.**
- **파일 만드는 부분이 앱과 분리돼 있습니다.** `pptx.js` · `xlsx.js` · `zip.js` 는 어느 화면에도
  기대지 않습니다. 다른 업무에 그대로 가져다 쓸 수 있습니다.
- 다음 단계로 붙이기 쉬운 것: 워드(.docx) 출력, 만족도 문항 표준화, 여러 사람이 볼 공용 저장소.

### 2. 사용 편의성

- **같은 값을 두 번 타이핑하지 않습니다.** 프로젝트에 한 번 넣은 고객사·인원·차수·기간·담당자 메일이
  제안서·결과보고서·견적서·메일 받는 사람까지 따라갑니다.
- **읽을 수 있는 것은 읽습니다.** 커리큘럼 PPTX·DOCX·PDF 에서 시간표를 뽑고, 만족도는 구글폼 표를
  붙여넣기만 하면 문항을 스스로 가릅니다.
- **못 하는 것은 못 한다고 말합니다.** 이미지는 글자를 못 읽어 원본을 옆에 띄우고, 스캔 PDF 는
  "PPTX 로 다시 받아 보세요" 라고 알려 줍니다. 읽은 척하지 않습니다.
- **위험한 것은 표시합니다.** 원가·이익률이 든 문서는 메일 첨부에서 기본으로 꺼져 있고 `내부용` 표시가 붙습니다.
- 빈 곳은 `빈칸 N군데` 로 계속 알려 줍니다. 무엇을 더 채워야 끝나는지 항상 보입니다.

### 3. 업무 활용성

수주 한 건에서 **손으로 하던 일이 이만큼 없어집니다.**

| 원래 하던 일 | 지금 |
|---|---|
| 교수님 커리큘럼을 보며 제안서에 옮겨 적기 | 파일 올리면 모듈 후보로 나옴 |
| 제안서 PPT 를 양식에서 복사해 고쳐 쓰기 | 양식 골라 누르면 채워진 파일이 나옴 |
| 견적서를 따로 엑셀로 만들기 | 예산 항목에서 자동 · 원가·이익률은 빠짐 |
| 제안가·이익률 계산기 두드리기 | 목표 이익률 넣으면 역산 |
| 만족도 엑셀 함수로 집계 | 붙여넣으면 문항별 평균·분포·NPS |
| 영수증 금액을 정산표에 옮겨 적기 | 처리한 증빙이 프로젝트별 계정으로 자동 합산 |
| 결과보고서 PPT 새로 쓰기 | 만족도·사진·정산이 들어간 파일이 나옴 |
| 메일 쓰고 파일 찾아 붙이기 | 받는 사람·제목·본문·첨부가 채워진 아웃룩 창 |

특히 **정산**은 제안 예산(계획)과 영수증(실제)을 같은 계정 체계로 묶어 놓아서,
따로 대조표를 만들 필요가 없어집니다.

### 4. 실제 도입 가능성

- **설치할 것이 거의 없습니다.** 파이썬 표준 라이브러리만 씁니다. 외부 패키지 `pip install` 없음,
  파워포인트·아웃룩 자동화용 `pywin32` 도 없음 — 윈도우에 늘 있는 PowerShell 로 부릅니다.
- **이미 쓰는 프로그램을 그대로 씁니다.** 새 계정도, 새 시스템 승인도 필요 없습니다.
  설치된 아웃룩·파워포인트를 그대로 부릅니다.
- **자료가 이 PC 밖으로 안 나갑니다.** 서버도 클라우드도 계정도 없습니다. 사내 보안 검토가 가벼워집니다.
- **폴더 하나가 전부입니다.** 복사해서 다른 PC 에 두고 `실행하기.bat` 을 누르면 그대로 돕니다.
  (작업 내용은 브라우저에 저장되므로 `백업` 으로 JSON 을 옮기면 같이 넘어갑니다)
- **반쪽으로도 돕니다.** 파이썬이 없으면 `index.html` 을 그냥 열어도 제안서 작성·만족도 분석·
  증빙·사진 정리는 다 됩니다. 메일과 PPT 양식만 빠집니다.

**아직 못 하는 것** (숨기지 않고 적습니다)

- 여러 사람이 같이 보는 기능이 없습니다. **한 사람의 PC 에서 한 사람이 씁니다.**
  같이 쓰려면 공용 저장소가 필요합니다.
- 윈도우 + 아웃룩(클래식) + 파워포인트가 있어야 메일·양식 기능이 됩니다. 새 아웃룩(Web 버전)은 확인하지 못했습니다.
- 사진 도구는 한 번에 한 건만 작업합니다.
- 이미지 속 글자(OCR)는 읽지 못합니다.

## 실행

**배포한 웹 주소로 들어가거나**, 이 PC 에서 `python relay.py`(또는 `실행하기.bat`)로 켭니다.
어느 쪽이든 PPT·엑셀·메일 기능이 모두 됩니다 — 파워포인트·엑셀·아웃룩이 켜져 있을 필요가 없습니다.

상단 탭(**프로젝트 · 제안서 · 결과보고서** | 전체 현황)이 항상 떠 있어 어디서든 바로 옮겨 다닐 수 있습니다.
`Esc` 를 누르거나 왼쪽 위 로고를 클릭하면 **프로젝트**로 돌아옵니다.
**화면을 오가도 작업 중이던 내용은 그대로 남습니다.** (새로고침하면 올린 이미지·사진은 비워집니다)

사이트 이름은 [`js/core/shell.js`](js/core/shell.js) 맨 위의 `SITE_ORG` · `SITE_NAME` 두 줄에서만 고치면
상단 로고·탭 제목·백업 파일명이 한꺼번에 바뀝니다. (`index.html` 의 `<title>` 과 로고는 첫 그림용 기본값입니다)

## 디자인

토스·당근처럼 쓰도록 기준을 잡았습니다.

**구조 — 런처가 아니라 현황판**
- 첫 화면은 도구 목록이 아니라 **지금 상태**입니다. 진행 중 프로젝트, 작성 중 제안서, 결과보고 대기 건을 실제 데이터로 보여 줍니다.
- **지표를 누르면 그 화면으로 바로 들어갑니다.** "결과보고 대기 1건"을 누르면 그 프로젝트가 열립니다.
- **상단 탭이 항상 떠 있습니다.** 홈으로 돌아갔다 다시 들어가지 않아도 도구 사이를 옮겨 다닐 수 있습니다.
- **한 화면은 한 화면 안에서** — 도구는 딱 화면 높이만 쓰고, 목록이나 폼처럼 긴 부분만 안에서 스크롤합니다.
- **한 화면 = 한 덩어리** — 도구 안의 탭은 이어진 막대로 묶어, 위쪽 도구 탭(파란 배경)과 역할이 다르다는 것이 보이게 했습니다.

**글꼴과 타이포**
- **Pretendard** 를 씁니다. 설치돼 있으면 그것을, 없으면 CDN에서 받아 씁니다. 사내망에서 CDN이 막혀 있으면 조용히 시스템 글꼴로 떨어질 뿐 기능에는 영향이 없습니다.
- 크기는 **네 단계만** 씁니다 — 화면 제목 25px, 카드 제목 15.5px, 본문 14.5px, 설명·라벨 12.5~13px. `styles.css` 맨 위 `--fs-*` 에 모여 있습니다.
- 한국어는 `word-break: keep-all` 로 어절 단위로 줄바꿈합니다. 숫자는 자리수가 흔들리지 않게 고정폭으로 씁니다.

**컴포넌트**
- **이모지를 전부 걷어냈습니다.** 아이콘은 24×24 격자에 선 굵기 1.7 로 통일해 직접 그렸습니다. 이모지는 OS 마다 다르게 보이고 굵기가 제각각이라 화면이 들쭉날쭉해 보입니다.
- **카드를 그림자로 띄우지 않고 1px 선으로 구분합니다.** 업무 화면은 정보가 촘촘해서 그림자가 많으면 금방 지저분해집니다. 마우스를 올렸을 때만 선이 한 단계 진해집니다.
- **입력은 시트로** — 회색으로 채운 큰 입력칸 + 아래 꽉 찬 파란 버튼 하나. 필수 항목은 파란 `필수` 뱃지.
- On/Off는 스위치, 여러 개 고르기는 칩, 알림은 아래 가운데 알약 토스트.
- 말투도 "저장했습니다" 대신 "백업 파일을 저장했어요" 로 바꿨습니다.

**완성도 손질 (마지막 정리)**

화면마다 조금씩 달랐던 것들을 하나로 모았습니다.

| 고친 것 | 왜 |
|---|---|
| **화면 머리를 한 가지로** | 프로젝트·제안서·결과보고서가 제목 크기도 여백도 제각각이었습니다. 이제 `제목 / 한 줄 설명 / 오른쪽 동작` 한 틀을 같이 씁니다. |
| **위쪽 띠 하나를 없앴습니다** | 도구마다 `설명 띠 → 탭 → 제목` 세 겹이 쌓여 있었는데, 설명이 제목 아래 문구와 같은 말이었습니다. 띠를 지웠습니다. |
| **탭을 이어진 막대로** | 따로 떨어진 알약들이 상단 도구 탭과 헷갈렸습니다. 지금은 한 덩어리 안에서 선택된 칸만 진해집니다. |

## 프로젝트 (첫 화면)

**고객사 × 과정 = 프로젝트 하나**입니다. 차수가 여러 개면 그 안에 묶습니다.

새 프로젝트를 만들 때 넣는 값(고객사·과정명·인원·차수·일수·기간·장소·담당자)은
제안서와 결과보고서가 그대로 받아 씁니다. 같은 걸 두 번 타이핑하지 않습니다.

목록에서는 단계별로 걸러 봅니다 — **제안 준비 · 제안 제출 · 수주 · 운영 중 · 결과보고 · 완료 · 무산**.

### 워크플로우 — 수주 한 건이 지나가는 여섯 칸

```
제안서 만들기 → 제안 발송 → [브리핑] → 수주 → 운영 → 결과보고서 만들기 → 결과 전달
```

프로젝트 카드마다, 그리고 프로젝트를 열면 이 여섯 칸이 **어디까지 왔는지**로 보입니다.
문서가 있느냐가 아니라 **일이 어디까지 갔느냐**를 봅니다.

**맨 위에 `다음 할 일` 한 줄**이 있습니다. 지금 해야 할 것 하나만 크게 적고, 누르면 그 화면이 열립니다.

| 상태 | 다음 할 일 |
|---|---|
| 제안서가 없다 | 제안서를 만드세요 |
| 제안서에 빈칸이 있다 | 제안서 빈칸을 채우세요 |
| 아직 안 보냈다 | 담당자에게 메일로 보내세요 |
| 보냈다 | 수주되면 단계를 바꿔 주세요 |
| 수주했다 | 교육이 시작되면 단계를 바꿔 주세요 |
| 운영 중이다 | 결과보고서를 만드세요 |
| 결과보고서가 다 됐다 | 고객사에 결과를 보내세요 |

**메일을 보내면 그 칸이 저절로 넘어갑니다.** 제안서를 보내면 단계가 `제안 준비 → 제안 제출` 로,
결과보고서를 보내면 `완료` 로 바뀝니다. 언제 누구에게 보냈는지도 칸에 남습니다.

> `바로 보내기` 로 보냈으면 `9/17 · 발송`, `아웃룩에서 열기` 로 넘겼으면 `9/17 · 아웃룩으로 넘김` 이라고 적습니다.
> 아웃룩 창에서 실제로 보냈는지는 이 앱이 알 수 없어서, 아는 만큼만 적습니다.

### 제안을 보내 놓고 잊지 않게 — 팔로우업

제안을 보낸 직후 **"다음 연락을 잡아 둘까요"** 창이 뜹니다.
`연락(회신 확인)` 또는 `브리핑 미팅` 과 날짜를 적어 두면:

- 그날이 되면 **프로젝트 목록 맨 위로 올라오고**, 위에 빨간 띠로 `오늘 연락할 곳 N` 이 뜹니다
- 전체 현황(홈)에 `오늘 연락할 곳` · `이번 주 연락` 이 숫자로 올라옵니다
- 프로젝트를 열면 `다음 할 일` 이 **담당자 이름과 메일 주소까지** 보여 줍니다
- 연락했으면 `했습니다` 한 번이면 됩니다

**브리핑 날짜를 적으면 단계가 자동으로 `브리핑` 으로 바뀝니다.**
지난 날짜는 `2일 지남` 처럼 빨갛게 표시합니다.

그 아래에 **제안서 · 결과보고서 두 장의 카드**, 그리고 **제안 예산(계획)** 과 **정산(실제)** 이 나란히 뜹니다.
계획 이익률과 실제 이익률을 한 화면에서 봅니다.

### 작성은 세 걸음으로

```
1 템플릿 고르기  →  2 커리큘럼 올리기  →  3 내용 작성
```

작성 화면 맨 위에 이 세 칸이 있고, **끝난 칸은 체크 표시와 함께 무엇을 골랐는지** 적힙니다
(`템플릿 ✓ KMA 제안서 표준양식`, `커리큘럼 ✓ 팀빌딩_커리큘럼.pptx`).
칸을 누르면 언제든 되돌아가 바꿀 수 있습니다.

1. **템플릿** — 올려 둔 PPT 양식이 썸네일로 깔립니다. 하나 고르면 다음으로 넘어갑니다.
   양식이 없으면 `양식 관리` 로 가서 올리거나, `기본 구성` 으로 진행합니다.
2. **커리큘럼** — 교수님이 보낸 파일을 올립니다. 없으면 `지금은 없습니다 — 건너뛰기`.
3. **내용 작성** — 통화 메모 · 제안 골격 · 과정 설계 · 운영 조건 · 사례 · 예산서와
   오른쪽 미리보기가 한 화면에 나옵니다.

> 전에는 이 셋이 한 화면에 섞여 있어서 **무엇부터 해야 하는지**가 안 보였습니다.
> 특히 템플릿을 맨 나중에 고르면 앞서 쓴 내용이 어느 장에 들어갈지 알 수 없었습니다.

### 1. 커리큘럼 파일 올리기

작성 화면 맨 위가 **커리큘럼 파일** 칸입니다. 끌어다 놓거나 클릭해서 고르면 글자를 뽑아 **모듈 후보**를 만들어 보여 줍니다. 체크한 것만 과정 설계에 들어갑니다.

| 파일 | 어떻게 처리하나 |
|---|---|
| **PPTX** | 슬라이드 순서대로 글자를 뽑습니다. 제목 자리표시자가 있으면 슬라이드 제목으로 씁니다 |
| **DOCX / XLSX** | 문단 · 셀 글자를 뽑습니다 |
| **PDF** | 글자를 뽑되, 스캔본이면 제대로 안 읽힙니다. 이때는 "PPTX·DOCX 로 다시 받아 보세요" 라고 알려 줍니다 |
| TXT · MD · CSV | 그대로 읽습니다 |
| **PNG · JPG** | **글자를 읽을 수 없습니다.** 대신 화면 옆에 원본을 띄워 두고 보면서 입력하는 용도입니다 |
| PPT · DOC · XLS (구버전) | 열 수 없습니다. PPTX·DOCX 로 다시 저장해 주세요 |

`09:00~10:30 팀 진단 워크숍 (1.5시간)` 같은 줄에서 **시간을 계산해 모듈 시간**으로 넣고, `1일차` 표기를 만나면 이후 항목에 일차를 붙입니다. 시간 정보가 있는 줄을 커리큘럼 항목으로 봅니다.

올린 원문은 **`세부 커리큘럼` 슬라이드에 그대로** 들어가고, `원문 N줄 보기` 로 언제든 다시 펼쳐 볼 수 있습니다.

### 2. 템플릿 — 쓰시던 PPT 양식을 그대로

**템플릿** 탭에 **회사 제안서 PPT 양식을 그대로 올리세요.** 여러 개 올려도 됩니다.

올리면 파워포인트가 그 파일을 열어 **장마다 그림을 뽑습니다.** 화면에는 양식이 썸네일로 깔리고,
장을 눈으로 보면서 **어느 장에 무엇을 채울지**만 고르면 됩니다.

| 고르는 값 | 뜻 |
|---|---|
| **그대로 두기** | 양식에 있는 글이 그대로 나갑니다 — 회사 소개·인사말처럼 안 바뀌는 장 |
| 표지 / 상황 / 문제 / 방향 / 과정 설계 / 커리큘럼 / 운영 / 기대효과 / 사례 / 예산 / 다음 단계 | 제안서에 쓴 내용이 그 장에 들어갑니다 |
| 고정 문구 | 직접 적어 둔 문장이 매번 들어갑니다 |
| **이 장 빼기** | 만들 때 그 장을 지웁니다 |

처음 올리면 **슬라이드 제목을 보고 짐작해서 미리 골라 둡니다** (`고객사 현황 분석`→상황, `소요 예산`→예산…).
틀린 것만 바꾸면 됩니다.

### 어떻게 채우나 — 새로 그리지 않고 양식 파일을 씁니다

제안서를 만들 때 **올려 둔 양식 파일을 열어 글자만 바꿔 저장합니다.**
디자인·배경·로고·글꼴이 전부 그대로 남습니다.

- **제목** — 제목 자리표시자가 있으면 거기에, 없으면 그 장에서 **맨 위에 있는 글상자**에 넣습니다.
- **본문** — 제목이 아닌 것 중 **가장 넓은 글상자**에 줄 단위로 넣습니다.
- **글이 없는 도형은 건드리지 않습니다.** 장식용 색 막대도 글상자라서, 빈 도형까지 넣으면 거기에 제목이 찍힙니다.
- 채울 내용이 비어 있으면 그 장은 손대지 않습니다. 양식 문구가 남으니 `빈칸 N군데` 를 보고 채우세요.

> **원본 양식은 안 바뀝니다.** 파워포인트에서 사본으로 열어 다른 이름으로 저장합니다.

양식을 안 올렸을 때는 **`기본 구성 (양식 없이 만들 때)`** 으로 나갑니다 —
표지 / 과정 개요 / 과정 설계 / 세부 커리큘럼 / 견적 / 다음 단계 여섯 장짜리 기본 디자인입니다.

빈 곳은 위쪽에 `빈칸 N군데` 로 계속 알려 줍니다.

### 4. 예산서 — PMS 등록용

인원·차수·일수만 넣으면 수량이 자동 계산됩니다. 견적 항목의 계정은 **증빙 도구와 같은 원가 구분 표**를 씁니다. 나중에 실제 정산할 때 제안 견적과 실제 계정을 그대로 맞춰 볼 수 있습니다.

| 수량 기준 | 계산 |
|---|---|
| 일수 | 일수 × 차수 |
| 인원 | 인원 × 차수 |
| 인원 × 일수 | 인원 × 일수 × 차수 |
| 고정 | 직접 입력 |

**제안가**를 넣으면 사업이익과 **사업이익률**이 바로 나옵니다. 반대로 **목표 이익률**(기본 25%)을 정해 두고 `목표대로 제안가 맞추기` 를 누르면 원가에서 역산해 천 원 단위로 올린 제안가를 넣어 줍니다.

```
제안가(공급가)   4,734,000원
부가세(10%)        473,400원
합계             5,207,400원
원가 합계        3,550,000원   (75%)
사업이익         1,184,000원
사업이익률              25%
1인당 제안가       157,800원   (원가 118,333원)
```

PMS 는 **계정 단위로 등록**하므로 같은 계정끼리 합친 표를 따로 보여 줍니다.

```
원)비상임강사료    1,600,000   45.1%
원)교육생숙식비    1,500,000   42.3%
원)교재비            450,000   12.7%
```

`PMS용 복사` 를 누르면 **탭으로 구분된 텍스트**가 복사돼 PMS 입력칸에 그대로 붙습니다.

| `…_커리큘럼.txt` | 올린 파일에서 뽑은 원문 그대로 |

### 검증 결과

PPTX 커리큘럼을 만들어 업로드부터 내보내기까지 브라우저에서 끝까지 돌렸습니다.

- **PPTX 추출** — 슬라이드 3장 10줄, `slide10` 이 `slide2` 뒤로 정렬됨(문자열이 아니라 숫자로 정렬)
- **모듈 변환** — `09:00~10:30 … (1.5시간)` → 1.5시간, `10:40~12:00` → 1.3시간(80분), `1일차`/`2일차` 자동 부착. 5개 후보 → 5개 모듈 반영, 합계 12.8시간
- **템플릿 import** — 10장짜리 양식 PPTX → 제목에서 `고객사 현황 분석`→상황, `커리큘럼`→커리큘럼, `유사 수행 실적`→사례, `소요 예산`→예산으로 자동 매핑
- **예산** — 강사료 2일×80만 + 교재 30명×1.5만 + 식대 60명·일×2.5만 = 원가 **3,550,000원**. 목표 25% 역산 → 제안가 **4,734,000원**, 부가세 473,400, 사업이익 1,184,000, 이익률 **25.0%**, 1인당 157,800원. 계정별 합계 3건 일치
- **개요서** — 11장, 2번이 '귀사의 상황', 6번 '세부 커리큘럼'에 원문 반영
- **내보내기** — .md / .txt / .csv / 커리큘럼.txt 네 개 모두 파일로 저장됨. CSV 값 전수 확인
- 375px 폭(휴대폰)에서 가로 넘침 없음, 네 도구 모두 오류 없이 열림

### 아직 안 한 것

- **이미지(PNG·JPG) 글자 인식** — 브라우저만으로는 OCR 이 안 됩니다. 읽는 척하지 않고 원본을 옆에 띄워 드립니다.
- **초안 문장 자동 작성** — 구조와 자리는 잡아 주지만 문장은 직접 쓰셔야 합니다. AI로 초안을 뽑으려면 API 키가 필요해 보류했습니다.
- **PPT 파일(.pptx) 생성** — 기존 KMA 디자인 양식을 살리기 어려워 개요서까지만 만듭니다.

## 결과보고서 (메인 2)

과정이 끝난 뒤 쓰는 문서입니다. 탭이 여섯 개입니다 —
**보고서 · 작성 · 만족도 · 정산·견적서 · 교육사진 · 영수증**.

제안서에 써 둔 커리큘럼과 예산을 그대로 이어받기 때문에, 같은 내용을 다시 넣지 않습니다.

### 만족도 조사

**구글폼 응답 시트나 엑셀 집계표를 표째로 복사해서 붙여넣습니다.** 파일을 따로 받을 필요가 없습니다.

어떤 열이 점수이고 어떤 열이 서술형인지 스스로 가릅니다.

| 열 모양 | 처리 |
|---|---|
| 5점·7점·10점 척도 숫자 | 문항으로 보고 **평균 · 분포 · 긍정응답률 · 5점 환산**을 계산 |
| 글자 | **서술형 응답**으로 모아 수강생 의견 슬라이드에 넣음 |
| 타임스탬프 · 이메일 · 이름 · 소속 | 응답자 정보로 보고 통계에서 제외 |
| 숫자지만 척도 범위를 넘음 | **건너뛴 열**로 그대로 보여 줌 — 감추지 않습니다 |

- 머리글 한 줄 + 응답 여러 줄이면 **원본 응답**으로, `문항 / 점수` 두 열이면 **이미 집계된 표**로 읽습니다.
- 탭 구분이 있으면 탭으로, 없으면 쉼표(따옴표 안의 쉼표는 건드리지 않음)로, 그것도 없으면 두 칸 이상 공백으로 나눕니다.
- **`추천의향(0~10)` 문항은 NPS 로 따로 계산**하고 종합 만족도 평균에서는 뺍니다. 척도가 달라 섞으면 평균이 왜곡됩니다.
- 척도가 섞여 있어도(5점 문항 + 10점 문항) **5점 환산**으로 맞춰 비교합니다.

화면에는 종합 점수, 문항별 막대와 분포, 서술형 전체, 건너뛴 열이 나옵니다.

### 정산 (내부)

**제안서에 쓴 예산(계획)** 과 **실제 집행액**을 계정별로 나란히 놓고 차액·집행률을 냅니다.

실제 집행액은 **영수증 탭에서 처리한 증빙**에서 자동으로 옵니다.
영수증 처리 이력에 금액과 프로젝트 id 가 함께 남아, 그 프로젝트 것만 계정별로 합칩니다.
PMS 로 나가는 강사료처럼 영수증이 없는 항목은 `+ 직접 넣는 항목` 으로 추가합니다.

## 파워포인트 파일 (.pptx)

제안서도 결과보고서도 **바로 열리는 파워포인트 파일**로 나옵니다.
붙여넣을 개요 텍스트가 아니라, 더블클릭하면 파워포인트가 열리는 진짜 파일입니다.

만드는 길이 두 가지입니다.

| 어떤 템플릿이냐 | 어떻게 만드나 | 어디서 |
|---|---|---|
| **올린 PPT 양식** | 그 파일을 열어 **글자만 바꿔** 저장 | 파워포인트 (relay 경유) |
| 기본 구성 | 처음부터 **직접 그림** | 브라우저 안에서 |

기본 구성으로 만든 파일은 이렇습니다.

- 16:9 · 한 장에 제목 하나 + 불렛. 제목 아래 KMA 블루 선.
- 줄이 많은 장은 글자 크기를 12~16pt 사이에서 자동으로 줄여 한 장에 담습니다.
- 글꼴은 맑은 고딕. 모든 도형이 **평범한 텍스트 상자**라서 파워포인트에서 바로 고칠 수 있습니다.
- 회사 디자인을 입히려면 파워포인트에서 **[디자인] → [테마]** 를 고르면 됩니다.

### 만든 뒤에 PPT 를 손봤다면 — 고친 것이 날아가지 않습니다

가장 흔한 일이 이겁니다. 제안서를 뽑아 **파워포인트에서 문구를 다듬고 장을 하나 더 넣었는데,**
고객이 인원을 바꿔 달라고 해서 다시 뽑으면 손본 것이 전부 사라집니다.

그래서 `파일로 저장` 에 **`고친 PPT 에 바뀐 내용만 넣기`** 를 뒀습니다.

1. 파워포인트에서 손본 파일을 올립니다.
2. 앱이 그 파일을 훑어 **우리 장과 짝을 지어 보여 줍니다.**
3. 지난번 내보낸 뒤 **내용이 달라진 장만 미리 체크**되어 있습니다. 원하는 것만 더 고르거나 빼세요.
4. 체크한 장의 **글자만** 바뀝니다. 나머지는 손댄 그대로입니다.

- 장은 **번호가 아니라 제목으로 찾습니다.** 파워포인트에서 장을 더하거나 순서를 바꿔도 따라갑니다.
- 표지는 제목이 고객사·과정명이라 그 글로 찾고, 못 찾으면 첫 장으로 봅니다.
- 제목까지 바꿔 버린 장은 못 찾습니다 — 그 장은 `못 찾았습니다` 로 표시하고 건너뜁니다. 파워포인트에서 직접 고치세요.

**세부적인 모양은 파워포인트에서 고치는 것이 맞습니다.** 이 앱이 건드리는 것은
제목 칸과 본문 칸의 **글자뿐**입니다. 도형 위치·색·글꼴·표·그림·애니메이션은 한 번도 건드리지 않습니다.

`.md` 개요 파일도 그대로 남겨 뒀습니다. 쓰시던 양식에 붙여넣고 싶을 때 쓰세요.

> 엑셀과 마찬가지로 라이브러리 없이 [`js/core/pptx.js`](js/core/pptx.js) 에 직접 만들었습니다.
> pptx 도 XML 여러 장을 zip 으로 묶은 것이라 같은 zip 모듈 위에 얹었습니다.
>
> 올린 양식 파일과 썸네일은 폴더 안 `templates/` 에 쌓입니다. 양식을 지우면 같이 지워집니다.

## 아웃룩으로 보내기

**만든 문서를 고객사 담당자에게 보내는 것이 이 사이트의 마지막 단계입니다.**
제안서·결과보고서 화면의 `메일` 단추를 누르면 아웃룩으로 이어집니다.

### 무엇이 자동으로 채워지나

| 칸 | 어디서 오나 |
|---|---|
| 받는 사람 | 프로젝트에 적어 둔 **담당자 메일** |
| 제목 | `[KMA 인재개발센터 2팀] 포스코인재창조원 신임팀장 팀빌딩 워크숍 제안서` |
| 본문 | 인사 → 과정 개요·제안가(또는 참석·만족도) → 맺음말 → 서명 |
| 첨부 | 제안서 `.pptx` + 견적서 `.xlsx` (결과보고서는 `.pptx` + 만족도 `.csv`) |

보내는 사람 이름·직급·연락처는 `내 정보` 에서 한 번만 넣으면 서명으로 계속 붙습니다.

### 내부용 문서는 빨갛게 표시됩니다

예산서와 정산표에는 **원가와 사업이익률**이 들어 있습니다. 고객에게 나가면 안 되는 숫자입니다.

- 첨부 목록에서 **기본으로 꺼져 있고**, `내부용` 표시가 붙습니다.
- 그래도 체크하면 노란 경고가 뜨고, 보내기 전 확인 창에도 한 번 더 나옵니다.
- 사진 zip 을 메일로 보낼 때는 **정산표를 아예 빼고** 다시 묶습니다.

### 메일 파일 만들기

`메일 파일 만들기` 를 누르면 **메일 파일(.eml)** 이 내려받아집니다. 그 파일을 열면
아웃룩이 **보내지 않은 새 메일**로 엽니다 — 받는 사람·제목·본문·첨부가 다 채워진 채로.
눈으로 보고 [보내기]만 누르면 됩니다.

예전의 '바로 보내기' 는 없앴습니다. 고객에게 가는 메일은 사람이 한 번 보고 보냅니다.

### 어떻게 만드나

```
브라우저 → /api/outlook/mail → server/mail.py → .eml (X-Unsent: 1)
```

- 아웃룩을 부르지 않으므로 **배포한 웹에서도, 맥에서도** 똑같이 됩니다(실행하기.bat 불필요).
- 한글 첨부 파일명은 표준(RFC 2231)과 아웃룩이 잘 읽는 모양(RFC 2047)을 같이 적습니다.
- 첨부 합계 **20MB**, 최대 12개까지. 넘으면 미리 막고 알려 줍니다.

## 외부용 견적서 (엑셀)

내부 예산서에는 원가와 사업이익률이 들어 있습니다. **그건 밖으로 나가면 안 됩니다.**
그래서 고객에게 보낼 견적서는 버튼 하나로 따로 뽑습니다.

**`외부용 견적서` 버튼은 두 곳**에 있습니다 — 제안서의 **예산서** 카드, 결과보고서의 **정산·견적서** 탭.
같은 화면을 열고 같은 내용을 씁니다.

나가는 것은 **항목 · 단가 · 수량 · 차수 · 견적가 · 소계 · 합계**뿐입니다.
원가, 사업이익, 사업이익률, 계정과목(`원)비상임강사료` 같은 내부 계정명)은 **한 글자도 들어가지 않습니다.**

### 예산 항목에서 자동으로

예산서에 단가를 넣은 항목이 그대로 견적 줄이 됩니다. 수량 기준을 네 칸으로 펴서 넣습니다.

| 예산서의 수량 기준 | 견적서에서 |
|---|---|
| 일수 | 단가 × **일수**일 × 1 × 차수 |
| 인원 | 단가 × **인원**명 × 1 × 차수 |
| 인원 × 일수 | 단가 × **인원**명 × **일수**일 × 차수 |
| 고정 | 단가 × **수량**식 × 1 × 차수 |

강사료 계정(`비상임강사료`·`컨설턴트급여`)은 **강사료** 묶음, 나머지는 **운영비** 묶음으로 나누고 묶음마다 소계를 붙입니다.
묶음 이름·항목명·단가·수량은 견적서 화면에서 바로 고칠 수 있고, 줄을 더하거나 뺄 수도 있습니다.

**부가세 면세 / 별도**와 **합계 천단위 절사**를 켜고 끌 수 있습니다.
견적 합계가 제안가와 다르면 노란 띠로 알려 주고, 한 번에 맞출 수 있습니다.

### 엑셀 파일

`엑셀로 저장 (.xlsx)` 을 누르면 진짜 엑셀 파일이 만들어집니다. 전달주신
`(견적서)클라우드네트웍스 대리과장 승진자과정_KMA.xlsx` **양식을 그대로 옮겼습니다** —
열 너비, 행 높이, 병합, 테두리, 표시형식, 셀 주소까지 같습니다.

```
B2      견적서                         (26pt 굵게, B2:T2 병합)
B5      ○○○ 귀중                       I5:T10  공급자 (등록번호·법인명·대표·소재지·업태·종목·전화·FAX)
B9      ◼ 금액 :  D9 =O17              [DBNum4] 서식 → 금삼백삼십만오천원정
B12     항목 | 단가 | 수량(단위) | 수량(단위) | 차수 | 견적가 | 비고
B13     강사료 | 대리과장 승진자 과정 | 400,000 | 8회 | 1 | 1차수 | =F13*I13*L13*O13
D14     소계                            R14 =SUM(R13:R13)
B17     합계(vat 면세)                  O17 =ROUNDDOWN(R14+R16,-3)
B18     * 본 교육과정은 부가가치세 면세로 진행됩니다.
```

**값이 아니라 수식으로 씁니다.** 파일을 받아서 단가나 수량을 고치면 견적가·소계·합계·한글 금액이 같이 바뀝니다.

공급자 정보(등록번호 105-82-01810, (사)한국능률협회 …)는 기본값으로 들어 있고,
`공급자 정보` 버튼에서 한 번 고치면 이 PC 에 남아 다음 견적서부터 계속 쓰입니다.

> 엑셀 쓰기는 라이브러리 없이 [`js/core/xlsx.js`](js/core/xlsx.js) 에 직접 만들었습니다.
> xlsx 는 XML 몇 장을 zip 으로 묶은 것이라, 이미 있던 zip 모듈 위에 얹었습니다.

### 교육사진 · 영수증

두 도구를 결과보고서 안에 그대로 띄웁니다.

## 합친 방식

여러 앱을 iframe 으로 얹지 않고 **한 페이지 안의 모듈로 합쳤습니다.** iframe 은 로컬 파일로 열 때 막힐 수 있고, 저장소와 백업이 따로 놀기 때문입니다.

```
kma-workspace/
  index.html            한 페이지
  styles.css            공용 디자인 (모든 도구가 같은 규칙을 씁니다)
  relay.py              로컬 서버 + 아웃룩 연결 (실행하기.bat 이 띄웁니다)
  js/core/ui.js         알림 · 확인 · 입력 시트 · 표 · 진행 표시
  js/core/shell.js      사이트 이름 · 상단 탭 · 화면 전환 · 현황판 · 통합 백업
  js/core/pptx.js       파워포인트(.pptx) 쓰기 — 라이브러리 없이 직접
  js/core/xlsx.js       엑셀(.xlsx) 쓰기 — 라이브러리 없이 직접
  js/apps/project/      프로젝트 — 나머지를 묶는 뼈대
  js/apps/proposal/     제안서 (office.js = PPTX·DOCX·XLSX·PDF 글자 추출)
  js/apps/report/       결과보고서 (survey.js = 만족도 붙여넣기 파싱·통계)
  js/apps/quote/        외부용 견적서 (excel.js = KMA 견적서 양식 그대로)
  js/apps/mail/         아웃룩으로 보내기 (본문 자동 작성 · 첨부 고르기)
  js/apps/receipt/      증빙 — 결과보고서의 '영수증' 탭에 실려 들어갑니다
  js/apps/photos/       교육사진 — 결과보고서의 '교육사진' 탭에 실려 들어갑니다
  js/apps/_ops-보류/     과정 운영 관리 — 빼 뒀지만 지우지는 않았습니다
  js/apps/_고객사-보류/   고객사 관리(노션) — 빼 뒀지만 지우지는 않았습니다
```

> **고객사 관리는 뺐습니다.** 노션에서 재접촉 대상을 찾아 주던 화면인데, 지금은 프로젝트가
> 그 자리를 대신합니다. 코드는 `js/apps/_고객사-보류/` 에 그대로 있어서, 다시 쓰려면
> `index.html` 의 script 세 줄과 `shell.js` 의 `NAV_IDS` 에 `'customers'` 만 되돌리면 됩니다.
> (노션 중계 코드는 relay.py 에서 빠졌으니 그 부분은 되살려야 합니다)

각 앱은 `mount(host)` / `unmount()` / `stat()` / `metrics()` / `exportData()` / `importData()` 만 셸에 알려 주면 되도록 했습니다. 도구를 다시 넣거나 새로 붙일 때도 `shell.js` 의 목록과 `index.html` 의 script 태그에 한 줄씩만 더하면 됩니다.

**증빙·교육사진을 결과보고서 안에 넣은 방식** — iframe 이 아니라 같은 `mount(host)` 를 결과보고서 탭 안의 칸에 대고 부릅니다. 탭을 옮길 때 `unmount()` 로 정리합니다. 그래서 두 도구는 상단 탭에서는 사라졌지만 코드도 데이터도 그대로이고, 통합 백업에도 계속 실립니다.

**도구 사이를 잇는 값 세 가지** — 프로젝트 id 하나로 묶습니다.

| 어디서 | 무엇이 | 어디로 |
|---|---|---|
| 프로젝트 | 고객사·인원·차수·기간·장소·**담당자 메일** | 제안서 · 결과보고서 개요 · 메일 받는 사람 |
| 제안서 | 예산(계정별 계획액) · 커리큘럼 원문 | 결과보고서 정산 · 커리큘럼 장 |
| 영수증 | 처리 이력의 금액 + 계정 + 프로젝트 id | 결과보고서 정산의 실제 집행액 |

**커리큘럼 파일을 읽는 건 전부 브라우저 안에서 합니다.** PPTX·DOCX·XLSX 는 ZIP + XML 이라 직접 풀어 `<a:t>`·`<w:t>`·공유문자열을 뽑고, PDF 는 스트림을 풀어 ToUnicode 표를 만든 뒤 글자를 꺼냅니다. 파일이 서버로 나가지 않습니다.

앱 안의 기능 코드(파일명 규칙, PDF 변환, EXIF 처리, 규칙 검증, zip 생성)는 **따로 검증한 것을 그대로 옮겼습니다.** 바꾼 것은 화면을 붙였다 떼는 부분과 이름 충돌뿐입니다.

### 프로젝트 → 결과보고서 전 구간

포스코인재창조원 팀빌딩 워크숍 한 건을 실제로 만들어 끝까지 돌렸습니다.

- **프로젝트 생성** → 제안서 카드 클릭 → 고객사·인원 30명·2일·1차수가 채워진 제안서가 만들어지고 연결됨
- **예산(계획)** 강사료 2일×80만 + 교재 30명×1.5만 + 식대 60명·일×2.5만 = 3,550,000 → 목표 25% 역산 제안가 **4,734,000원**
- **만족도** 구글폼 8열 × 7응답 붙여넣기 → 점수 문항 4개 · 서술형 2개 인식, 타임스탬프·이메일은 **건너뛴 열**로 분리, `추천의향(0-10)` 은 NPS 43 으로 따로 계산되고 종합 평균에서 제외 → 종합 **4.34 / 5.0**
- **정산** 영수증 4건 중 이 프로젝트 것 3건만 집계(2,680,000원) → 계정별 차액 산출, 실제 사업이익률 **43.4%** (계획 25%)
- **결과보고서 12장** 생성 — 출석률 93% · 수료율 100% · 응답률 25% 자동 계산, 수강생 의견 9건 반영
- **내보내기** 개요 .md / 정산 .csv / 만족도 .csv / zip 네 가지 모두 파일로 저장. zip 안에 4개 항목(보고서·정산·만족도·만족도 원문) 확인
- 사진 도구를 한 번도 열지 않은 상태에서 zip 을 만들면 사진 없이 정상 생성 (초기 버전에서는 여기서 멈췄고, 고쳤습니다)

### PPT 양식 · 파워포인트 · 아웃룩

**양식 올리기 → 채우기** — 6장짜리 양식을 올려 제안서를 만드는 데까지 돌렸습니다.

- 올리자마자 파워포인트가 장마다 PNG 를 뽑았고, 화면에 썸네일 6장이 깔림
- 제목을 보고 `표지 / 과정 설계 / 커리큘럼 / 견적 / 다음 단계` 5장이 자동으로 골라졌고, 나머지는 `그대로 두기`
- 그 양식으로 제안서를 만들어 파워포인트로 열어 확인 — **양식 디자인 그대로, 글자만 바뀜**
  - 표지에 제목·수신·날짜가 들어가고 제목이 두 번 들어가지 않음
  - `그대로 두기` 로 둔 2번 장은 양식 문구가 그대로 남음
  - 채울 내용이 빈 장은 손대지 않음
- **장식용 색 막대에 제목이 찍히던 것**을 고쳤습니다 — 글이 이미 들어 있는 도형만 건드립니다
- 원본 양식 파일은 바뀌지 않는 것까지 확인

**고친 PPT 에 다시 넣기** — 실제로 손을 댄 뒤 다시 넣는 데까지 돌렸습니다.

2. 파워포인트에서 **`KMA 소개` 장을 3번 자리에 새로 넣고**(7장이 됨),

### 외부용 견적서

전달주신 실제 견적서(클라우드네트웍스 대리과장 승진자과정)를 **같은 값으로 다시 만들어** 견줬습니다.

- 강사료 400,000 × 8회 × 1 × 1차수 = **3,200,000** · 교재비용 15,000 × 7명 = **105,000** · 합계 **3,305,000** — 원본과 일치
- 한글 금액 **금삼백삼십만오천원정** — 원본의 `[DBNum4]` 결과와 일치
- 만들어진 파일을 열어 셀 주소를 대조: `B2·B5·B9·D9·B12·B13·D14·B17·O17·B18` 과 수식 `=F13*I13*L13*O13`, `=SUM(R13:R13)`, `=ROUNDDOWN(R14+R16,-3)` 까지 **원본과 같은 자리**
- 파일 구조 검사 — 중복 셀 없음, 행·열 순서 오름차순, 병합 47개 겹침 없음, 스타일 선언 수와 실제 수 일치(글꼴 11 · 채우기 3 · 테두리 27 · 서식 86), 스타일 인덱스 범위 정상
- 부가세 별도 + 천단위 절사도 확인: 3,308,500 → 절사 **3,308,000**, 부가세 330,800, 총 3,638,800 이 하단 문구까지 반영됨
- 한글 금액 변환 확인: 1,000 → 금일천원정 / 120,500,000 → 금일억이천오십만원정 / 1,000,000,000 → 금일십억원정
